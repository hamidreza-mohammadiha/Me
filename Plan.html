How a GitHub branch, a disposable Codespace, and a lightweight local test database fit together — and the exact seam where you swap the local pieces for hosted ones once you're ready to pay a little.

How the three pieces relate

1 · Branches

A branch is just a name for a line of work

Each branch (main, feature/x, friend-test) is a snapshot of your code. Branches don't run anything by themselves — they're the thing a Codespace gets built from.

2 · Codespaces

A disposable container per branch

Open a Codespace on a branch and GitHub spins up a full Linux VM with your repo checked out. Inside it you run your app and a small local database (SQLite file, or Postgres/MySQL in a dev container) purely for tests — no external DB needed yet.

3 · OpenRouter

The only thing that actually costs money here

Your app calls OpenRouter's API for LLM responses. This is metered per token, so it's where your $10–100 test budget actually gets spent — everything else above stays on free tiers.

Why this setup is free to prototype

GitHub Codespaces free tier gives every account roughly 120 core-hours and 15 GB storage a month at no cost — enough to spin up a Codespace per branch, poke at it, and let it auto-sleep when idle. Your local database lives inside the Codespace's disk (SQLite file or a containerized Postgres started with docker compose up), so there's no hosted database bill while you're the only one testing. The only variable cost is OpenRouter tokens, which you control directly by choosing cheaper models (e.g. Llama or Mistral variants) during early testing and reserving pricier models for final passes.

The seam where you spend real (small) money

StageWhere data livesCostTrigger to move on
Solo prototyping SQLite file inside Codespace $0 Works alone, no persistence needed between sessions
Testing with friends Postgres container inside Codespace, or Codespaces port-forwarded temporarily $10–100 in OpenRouter tokens More than 1–2 people need to hit it at once, or a Codespace idling out mid-test is annoying
Small shared/production use Neon, Supabase, or Turso (all have generous free Postgres/SQLite-compatible tiers) $0–5/mo You want a stable URL that's up 24/7 without a Codespace running
The move from row 2 to row 3 is deliberately small: if your app reads its database URL from a single environment variable (e.g. DATABASE_URL), converting means creating a free Neon/Supabase project, copying its connection string into that variable, and running your existing migrations against it once. Nothing about your branches, Codespaces, or OpenRouter calls needs to change.
